## 1. 概要
小説の執筆において、独自の世界観を深めるための「架空言語（コンラング）」をAI（Gemini等）を用いて自動生成し、管理するツールです。
言語学的な整合性を保ちつつ、ユーザーの好みに合わせた言語（例：エルフ風、機械語風、荒々しい部族の言葉など）を提案し、執筆のインスピレーションを与えます。

## 2. 主要機能

### 2.1 言語の新規生成
ユーザーが入力したパラメータに基づき、AIが言語の体系を段階的に構築します。
*   **入力パラメータ**:
    *   言語名
    *   キーワード（例：「幻想的」「鋭い」「古代」「魔法」）
    *   目的・コンセプト（例：「砂漠の民が使う、乾燥した響きの言葉」）
    *   音韻スタイル（柔らかい、荒々しい、単純、複雑、等）
    *   文法的複雑さ（極めて単純 〜 極めて複雑）
    *   文化的テーマ（遊牧民、高度文明、深海など）
    *   着想の元（既存の言語系統など）
*   **生成プロセス (段階的生成)**:
    1.  **コンセプトの具体化**: AIによる詳細な設定の生成。
    2.  **音韻論 (Phonology)**: 音素、音節構造、アクセント規則。
    3.  **形態論 (Morphology)**: 語形成、活用、接辞、語派（孤立語、膠着語など）。
    4.  **統語論 (Syntax)**: 語順（SVO, SOV等）、文構造。
    5.  **文字体系 (Writing System)**: 体系の種類（音素文字、音節文字等）、美的感覚の説明。
    6.  **初期語彙 (Vocabulary)**: 数十語程度の基本的な単語（名詞、動詞、形容詞等）。
    7.  **例文 (Example Sentences)**: 文法と語彙に基づいた挨拶や基本的な文章。
    8.  **背景設定 (History)**: 言語の由来や話者の背景。

### 2.2 言語の管理・閲覧
生成された言語はプロジェクトデータの一部として保存され、いつでも閲覧・修正が可能です。
*   **一覧表示**: 作成済み言語の管理。
*   **詳細表示**: 各カテゴリ（音韻、文法、辞書等）の閲覧。
*   **修正**: AIが生成した内容に対する手動調整。
*   **ファイル保存・管理**: 言語ごとに専用のフォルダを作成し、カテゴリ別の Markdown ファイルとして保存します（詳細は第3章参照）。
*   **インポート/エクスポート**: JSON形式によるデータの外部持ち出し。

### 2.3 語彙・例文の拡張
*   **語彙の追加生成**: 既存の音韻論・形態論に従った新しい単語のオンデマンド生成。
*   **例文の追加生成**: 特定のシチュエーションに応じた例文の生成。

## 3. データ保存仕様

ユーザーによる直接の閲覧・編集（可読性）を最優先し、1つの言語を1つの専用フォルダに集約し、内容ごとにファイルを分割する **「マルチファイル構成」** を採用します。

### 3.1 フォルダ構成例
`言語/[言語名]/`

*   **`[言語名].md`**: 言語の基本プロファイル。
    *   フロントマター: `type: conlang-meta`
    *   内容: ID、言語名、生成時に使用したパラメータ（キーワード、文化的背景等）、作成/更新日時。
    *   *注: フォルダ名と同じファイル名を持つこのファイルが、言語の「顔」となります。*
*   **`history.md`**: 言語の歴史、文化的背景。
    *   フロントマター: `type: conlang-history`
    *   内容: 由来、話者コミュニティ、変遷などの詳細テキスト。
*   **`phonology.md`**: 音韻論。
    *   フロントマター: `type: conlang-phonology`, `phonemes: [...]` (構造化データ)
    *   内容: 音素の解説、音節構造、アクセント規則のテキスト。
*   **`grammar.md`**: 文法体系（形態論・統語論）。
    *   フロントマター: `type: conlang-grammar`
    *   内容: 語形成、語順、時制、格などの規則。
*   **`vocabulary/` (ディレクトリ)**: 語彙（辞書）データ。
    *   フォルダ内の複数の Markdown ファイル（例: `nouns.md`, `verbs.md` または `index.md`）で構成。
    *   各ファイル: `type: conlang-vocabulary`
*   **`writing_system.md`**: 文字体系。
    *   フロントマター: `type: conlang-writing`
    *   内容: 文字の仕組み、美的解説、サンプルテキスト。
*   **`examples.md`**: 例文。
    *   フロントマター: `type: conlang-examples`, `sentences: [...]` (構造化データ)
    *   内容: 例文とその意訳、文法解説。

### 3.2 識別の仕組み
*   **メタデータ優先**: ファイル名によらず、フロントマターの `type` フィールドを確認することで、本ツールは各ファイルがどの役割（音韻、文法等）を担っているかを判別します。
*   **階層構造の利用**: `vocabulary/` フォルダ以下にあるファイルは自動的に語彙データとしてスキャンされます。

## 4. UI/UX設計 (novelaid-editor-next への統合)

### 4.1 サイドパネル
*   `ConlangPanel` をサイドパネル（右側）に追加。
*   作成済み言語の一覧を表示し、ワンクリックで詳細ビューを開けるようにします。

### 4.2 生成ウィザード (Dialog/Modal)
*   パラメータを入力する多段フォーム。
*   生成中は「音韻を構築中...」「基本語彙を考案中...」といった進捗を表示し、ユーザーを飽きさせない演出を行います。

### 4.3 言語詳細ビュー
*   タブ形式またはセクション形式で各情報を表示。
    *   **概要**: 背景設定、コンセプト。
    *   **辞書**: 単語の検索・一覧。
    *   **文法**: 音韻、形態、統語のルール。
    *   **文字**: 文字体系の説明とサンプル。

## 5. 技術仕様
`GenLang` の `Conlang` 型をベースにしつつ、Markdown へのシリアライズ/デシリアライズを考慮します。各ファイルはフロントマターの `type` タグによって役割を識別します。

## 6. AI 実装方針 (自律型協調エージェント)
`novelaid-ai` および `restar-ai` のエージェント・ペルソナシステムを活用し、単一のプロンプトではなく、複数の役割を持ったAIが自律的に検討・修正・連携を行うデザインを採用します。

### 6.1 役割分担 (Personas)
以下の専門的なペルソナを定義し、それぞれの視点から言語を構築します。

1.  **言語学者 (Linguist Persona)**:
    *   **担当**: 音韻論、形態論、統語論の設計。
    *   **役割**: 自然言語としての妥当性、音の響きの整合性、文法ルールの体系化。
2.  **世界構築者 (World Builder Persona)**:
    *   **担当**: 文化的テーマ、歴史的背景、コンセプト、語彙の意味定義。
    *   **役割**: その言語が使われる世界の文化や歴史に基づいたリアリティの付与。「なぜその言葉が生まれたか」の動機付け。
3.  **編纂エージェント (Coordinator Agent)**:
    *   **担当**: 生成プロセスの進行管理、各ペルソナの出力の統合、矛盾の検知。
    *   **役割**: 言語学者の設計と世界構築者の設定に矛盾がないか（例：乾燥した砂漠の民なのに、湿度を感じさせる音が多い等）をチェックし、必要に応じて修正を指示する。

### 6.2 生成ワークフロー
1.  **計画フェーズ**: 編纂エージェントがユーザーの入力を分析し、生成の基本方針を策定。
2.  **構成フェーズ**: 
    *   言語学者が音韻・文法のドラフトを作成。
    *   世界構築者がそのルールに基づき、文化的背景と初期語彙を考案。
3.  **検討・修正フェーズ**: 
    *   編纂エージェントが両者の出力をクロスチェック。不整合があれば、修正案を添えて各ペルソナに再検討を依頼。
    *   ユーザーに中間報告を行い、フィードバックを反映。
4.  **最終化フェーズ**: 全てのパーツを統合し、構造化されたデータ（Markdown/JSON）として出力。

### 6.3 技術的アプローチ
*   **Persona Registry**: `builtin.ts` と同様に、架空言語専用のペルソナを登録。
*   **Agent Pipeline**: `restar-ai` の Pipeline 機能を拡張し、順次・反復的な生成プロセスを実装。
*   **構造化出力**: `response_mime_type: "application/json"` と JSON Schema を活用し、ペルソナ間のデータ受け渡しを確実に行います。

## 7. 今後の発展性
*   **自動翻訳（変換）支援**: 本文中の特定の単語を、作成した架空言語の単語へ置換する機能。
*   **辞書連携**: エディタの「設定」や「世界観メモ」に語彙を自動登録。
*   **画像生成連携**: 文字体系の説明から、その文字を用いた石碑や書物のイメージを画像生成する。
