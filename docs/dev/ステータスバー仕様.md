# ステータスバー仕様

## 1. 概要と設計理念

ステータスバーは、小説執筆エディタの最下部に常駐し、現在編集中のドキュメントの基本情報（ファイル名、形式）、リアルタイムな文字数・行数などの各種メトリクス、画面レイアウトの切り替え、設定へのアクセスなどの操作インターフェースを作家に提供する重要なUIコンポーネントです。

### 1.1. 小説執筆におけるステータスバーの理念
1. **書いた実感をリアルタイムに可視化（モチベーションの源泉）**:
   作家にとって「いま何文字書いたか」「原稿用紙何枚分進んだか」は、執筆のペースとモチベーションを維持する上で不可欠なフィードバックです。
2. **執筆の思考を邪魔しない静かなUI**:
   エディター最下部（高さ24〜28px）に溶け込み、執筆中は視界の端で静かに情報を保ちつつ、必要なときだけクリックして詳細な文体分析（セリフと地の文の比率など）を閲覧できます。
3. **選択範囲の即座な推敲支援**:
   推敲時に段落やシーンを選択するだけで、選択部分の文字数が即座にハイライト表示され、文字数制限のあるシーンの調整が容易になります。

## 2. 現行仕様（novelaid-editor）

現行の `novelaid-editor` におけるステータスバーは、以下の構成および機能を持っています。

### 2.1. 画面レイアウト
- **配置**: アプリケーションウィンドウの最下部に全幅（100vw）で配置されます。
- **高さ**: 24〜28px。
- **構造**: Flexbox を使用して、左側の操作・ファイル情報グループと、右側の分析・アクションボタンのグループに分かれています。

### 2.2. 左側グループ（操作・基本情報）
1. **ホームボタン (Home)**: エディタ画面から書庫一覧（プロジェクトランチャー等）へ戻ります。
2. **左サイドパネルトグル (PanelLeft)**: 左サイドバー（ファイルエクスプローラー等）の表示/非表示を切り替えます。
3. **設定ボタン (Settings)**: エディタ設定ダイアログを開きます。
4. **ファイル情報表示 (File Info)**:
   - ドキュメント種別アイコン（`DocumentIcon`）
   - ファイル名 (例: `01_プロローグ.md`)
   - ドキュメント種別タグ (例: `Novel`, `Markdown`)
5. **メタデータ非同期同期進捗 (Scan Progress)**:
   - バックグラウンドで原稿スキャンが実行されている間、回転アイコンとともに `同期中... 45%` のように進捗を表示。

### 2.3. 右側グループ（分析・状態表示）
1. **文字数・行数表示エリア (Metrics Display)**
   - **通常時**: 基本文字数（空白・改行除く）と総行数を表示。
     - 表示例: `文字数: 3,450 行数: 120`
   - **テキスト選択時**: 選択範囲内の基本文字数を動的に表示。
     - 表示例: `選択中: 150 / 3,450`
   - **インタラクション**: クリックすることで「文字数詳細分析ポップアップ」を開閉。
2. **右サイドパネルトグル (PanelRight)**: 右サイドバー（メタデータパネル等）の表示/非表示を切り替えます。
3. **フルスクリーン切り替えボタン (Fullscreen)**: アプリケーションのフルスクリーン表示を切り替えます。

### 2.4. 文字数詳細分析ポップアップ
文字数表示エリアをクリックすると表示される上向きフロートUIです。`novelaid-ruby` パッケージの `countCharacters` 関数から返される `DetailedCountResult` を元に、以下の詳細なメトリクスを表示します。

- **基本カウント**:
  - 基本文字数（空白・改行除く、カクヨム/なろう標準）
  - 文字数（空白・改行含む、システム上限用）
  - 総文字数 (RAW長)
  - 総行数
  - 原稿用紙換算枚数 (400字詰め換算、20字×20行基準)
- **文体分析（セリフと地の文の比率）**:
  - セリフ（カギ括弧 `「` `『` 等で始まる行）と地の文の文字数および行数。
  - セリフ比率 vs 地の文比率をツートンカラーのプログレスバーで可視化。
- **空白・改行内訳**:
  - 全角スペース数、半角スペース数、改行コード数

### 2.5. パフォーマンス考慮（Debounce）
長文執筆時の入力パフォーマンス（タイピングの応答性）を維持するため、エディタのテキスト変更イベントから以下の遅延処理を入れて文字数を再計算します。
- 全体文字数カウント: 150〜200ms のデバウンス
- 選択範囲文字数カウント: 即時または100msのデバウンス

## 3. 新世代仕様（novelaide）における実装と改善点

`novelaide`（Tauri 2.x + React 19 + TypeScript + Vite）では、以下の改善方針を確立しています。

1. **`novelaid-ruby` のフル活用**:
   文字数カウント・ルビ除外・原稿用紙換算の全ロジックを `novelaid-ruby` に完全委譲し、アプリ側の計算ロジック二重管理を排除。
2. **React 19 の `useDeferredValue` / `useMemo` による軽量化**:
   入力時のキーストロークを妨げずに、非同期・遅延でバックグラウンド計算を行い、数十万文字の長編原稿でも快適なタイピングを保証。
3. **カスタムイベントによる疎結合な選択範囲連動**:
   Monaco Editor の `onDidChangeCursorSelection` から発火される `editor-selection-change` イベントを購読し、エディターコンポーネントとステータスバーを疎結合に連携。
